# 平台数据源调研与接入边界（2026-11-11）

## 结论先行

| 平台 | 评分 | 房价 | 接入方式 | 说明 |
| --- | --- | --- | --- | --- |
| 去哪儿 Qunar | 否 | **是** | 百度地图聚合字段 `pc_price_src=qunar` | 页面已有，标注「Qunar (via Baidu Maps)」 |
| 携程 Ctrip | **是** | 否 | 公开 SEO 列表页（名称、星级、评分、点评数） | 房价需登录态/签名会话 |
| Trip.com（携程集团） | 否 | 部分 | 公开 SEO 列表页仅 5 家精选酒店含价格 | 无法按酒店稳定取价，未接入 |

| 美团 Meituan | 否 | 否 | `ihotel.meituan.com/hbsearch/HotelSearch` | 匿名 403，需 `mtgsig` 签名 |

**没有用任何伪造签名或登录态去绕过平台风控**；取不到的价格显示为不可用，不用估算值冒充。

## 实测记录

1. 百度地图聚合：抽取北京/上海/成都/乌鲁木齐/拉萨 40 家酒店，`price_source` 全部为
   `Qunar (via Baidu Maps)`，说明该渠道是真实的去哪儿报价，但不是携程/美团报价。
2. 携程公开列表页
   `https://hotels.ctrip.com/hotels/list?city=1&checkin=...&checkout=...`
   返回 200、约 1.3MB SSR HTML，含酒店中文名、星级、评分（如 4.8）、点评数（如 6,603 条点评）；
   房价区为客户端渲染，SSR 无价格。
3. 携程列表 JSON `restapi/soa2/34951/fetchHotelList`：补齐 `head.group`、`dateType` 后返回
   `Ack=Success` 但 `data` 为空；详情聚合 `33278/getHotelDetailAggregate` 返回点评、位置、设施，
   `authInfo.isLogin=false`，无房价。
4. 同程 `m.ly.com` 列表页是 SPA，`__INITIAL_STATE__` 声明 `/tapi/v2/list` 等接口需要 `h5sign`；
   页面不含房价，匿名接口不可用。
5. 美团 `ihotel.meituan.com/hbsearch/HotelSearch` 403；`apimobile.meituan.com/group/v4/poi/pcsearch`
   404；`i.meituan.com/hotel/` 仅 JS 外壳。
6. Trip.com `www.trip.com/hotels/list?city=1` SSR 含 5 家精选酒店的名称与 `priceInfo`（USD），
   但不是按酒店的稳定查询接口，无法用于逐店比价。

## 当前实现

- `services/platforms.py`
  - 动态发现携程城市编号（公开静态城市接口 + 1–60 主要城市列表页标题探测，本地缓存）。
  - 解析携程公开列表页的酒店名称/星级/评分/点评数，与本地酒店按名称精确/模糊匹配。
  - `status()` 输出各平台能力：Qunar 价格、Ctrip 评分、同程/美团 blocked 原因。
- `/api/platforms` 返回平台状态；酒店详情的 `platform_ratings` 展示真实的 Qunar 报价与 Ctrip 评分，
  并明确标注「price needs platform session」。
- 设置抽屉新增「Platform sources」区块，逐平台展示 Live price / Ratings only / Blocked 及原因。

## 若必须做到三平台实时房价

1. **官方开放平台**：携程开放平台、同程开放平台、美团开放平台均需企业资质与商务签约，提供酒店库存/价格接口。
2. **持牌聚合服务**：采购 Apify/StayAPI 等付费接口，按调用量计费，需 API Key 与授权。
3. **用户登录态浏览器桥**：本地 Playwright 打开平台页面并由用户自行登录，再读取页面价格；属于个人使用场景，需遵守平台条款，且无法在零依赖、免配置前提下稳定运行。

在上述任一条件满足前，本项目不会把去哪儿单渠道价格包装成「三平台比价」。

### 接入规则（已实现，全部带来源标注）

- 去哪儿报价只在「与百度价量级接近（0.25–4 倍）」时作为第二渠道展示，避免把讲解/研学套餐当成门票；
- 百度缺价时，仅当去哪儿标注了 A 级（`star` 非空）且价格 ≤ 400 元才补，并注明来源为 Qunar direct；
- 百度价为 0（免费）的场馆不叠加去哪儿报价；
- 评分不合并、不平均：百度与去哪儿两个来源在详情页并列显示，各自带平台名与点评数。

| 套餐价误判 | 中共二大会址纪念馆 ¥550、中共四大纪念馆 ¥477、上海植物园 ¥288（实际免费或低价）→ 已被过滤规则挡掉 |

**本批结论**：门票价与评分从「单源」变成「景点双源」，但酒店房价/评分（去哪儿、携程、美团、同程均为签名或反爬）与机票、火车票票价依旧只能单源或估算，页面继续如实标注，不冒充第二来源。

## 花费口径（交通与住宿）

| 项目 | 真实来源 | 估算/假设部分 | 公式 |
| --- | --- | --- | --- |
| 高铁 | 车次号与起讫站来自 12306 `train_list.js` 时刻表（北京→上海 40 趟） | 票价与耗时为估算 | 票价 = 铁路里程（直线 × 1.18）× 0.46（二等）/ 0.74（一等）元/公里；耗时 = 里程 / 280 km/h + 18 分钟停站 |
| 飞机 | 无匿名报价源（携程/去哪儿需签名） | 票价与耗时全部为估算 | 票价 = 280 元 + 直线里程 × 0.35 元/公里，区间 ×0.75–1.35；耗时 = 里程 / 650 km/h + 120 分钟地面时间 |
| 自驾 | 92# 油价实时（icauto.com.cn，31 省挂牌价，缓存 6 小时） | 油耗 7.5 L/100km、通行费 0.45 元/公里、路网系数 1.22 | 油费 = 公路里程 / 100 × 7.5 × 油价；通行费 = 公路里程 × 0.45；耗时 = 公路里程 / 85 km/h |
| 酒店房价 | 百度地图网页检索返回的 OTA 实时报价（`pc_price_src` 多为去哪儿） | 星级、房型名称为平台口径 | 展示为「每晚起价」；行程总价 = 每晚价 × 住宿晚数，门票与住宿分列 |
| 景点门票 | 百度地图（在线参考价）+ 去哪儿门票频道（直连挂牌价） | 无（均为平台报价） | 最低价与价差按全部渠道报价计算 |

口径可在页面「这些数字怎么来的」中展开核对，接口字段为 `/api/transport` 的 `params`、`sources`、`as_of`。

**本批结论**：确实存在“已爬好的数据”，但没有一份能同时满足「免密钥 + 全国覆盖 + 含价格 + 许可清楚 + 体积可控」。可直接取用的只有 Wikidata（CC0、免密钥），覆盖面窄但可当官方标签层；OSM 派生集许可清楚但 367 MB 下载不现实；聚合类接口一律要用户自己的实名 key。因此工程策略保持：主力用内置百度地图网页源（免密钥、含价格与图片）+ 快照缓存兜底，Wikidata 仅用于世界遗产等官方标签与英文名补充，并在页面标注来源。

## 高德 / 同程票价能否作为数据源

**结论：不能把高德客户端里展示的同程价格当成可直接调用的数据源；合规做法只有走同程的授权 API。**

依据：

1. 高德开放平台的 POI 搜索接口（`/v3/place/text`、周边搜索）在 `extensions=all` 时返回 `biz_ext`，
   其中只有 `rating`（评分）与 `cost`（人均消费）；`ticket_ordering`、`hotel_ordering` 两个字段
   在官方文档中已标注“逐渐废弃”。接口没有景点票价、酒店房晚价，也没有库存或预订能力。
   文档：https://lbs.amap.com/api/webservice/guide/api/search
2. 高德地图开放平台服务协议明确禁止抓取与缓存客户端数据：3.5 条禁止“直接存储、缓存或技术手段抓取、
   使用本服务内部数据”；4.12.3 条禁止使用爬虫、抓取工具访问或缓存本服务内容；7.3 条禁止爬取、存储、
   镜像、复制、二次包装等。协议：https://lbs.amap.com/pages/terms/
3. 高德 App 内的酒店/门票预订是“聚合模式”，房源与票价由合作 OTA 提供，属于商务合作内容，
   不通过开放平台 API 对外输出。
4. 同程旅行联盟/分销平台提供 API 合作模式，但需要注册、提交合作项目、审核通过后由 BD 提供接口文档，
   并按分销/佣金体系结算；并非匿名可调用的公开价格接口。
   联盟合作：http://union.ly.com/web/unionco ；分销合作：http://union.ly.com/web/fenxiao
5. 同程商旅（TMC）另有 200+ 标准化 API，但面向企业差旅系统集成，需要合同与项目制接入。
   文档：https://tmc.ly.com/zh/platform/integration

可行路径（按成本从低到高）：

- **保持现状**：景点票价继续用去哪儿公开门票页做第二价格源；酒店房价继续用百度地图聚合报价。
- **申请同程联盟/分销 API**：拿到 AppKey/AppSecret 后接入门票与酒店报价，按返佣结算；需要企业资质与审核。
- **高德到店生态合作**：与高德商户/到店业务签合作，获得聚合内容的授权展示，不直接抓客户端。
- **不做**：抓包高德 App、模拟客户端请求、爬取同程 H5。违反平台协议，且签名/风控频繁变化，稳定性不可接受。

对演示站的影响：页面的“高德 / 同程票价”卡片按“合作授权专用”展示，不显示伪造价格；
在拿到授权前，票价与房价仍以现有公开源或“暂无报价”呈现。
